# TutorLanding

Демонстрационный одностраничный сайт частного репетитора по математике. Белая, молочная, графитовая и синяя палитра, адаптивная вёрстка и навигация по разделам.

Описание преподавателя, форматы и цены — примеры. Реальных контактов, отзывов и подтверждённых достижений нет. Кнопки записи переходят к разделу контактов; сайт не отправляет заявки.

## Файлы

- `index.html` — содержимое, семантическая разметка и метаданные.
- `styles.css` — оформление, адаптивность, фокус и уменьшение анимаций.
- `menu.js` — мобильное раскрывающееся меню.
- `favicon.svg` — векторная иконка вкладки.

Сборка, зависимости и серверная часть не нужны. Нет внешних шрифтов, библиотек, аналитики или платных сервисов.

## Как открыть

Откройте `index.html` в браузере. После изменений обновите страницу; если видна старая версия, используйте Ctrl+F5.

Для разработки можно использовать локальный статический сервер из редактора. Корнем сервера должна быть папка TutorLanding.

## Как опубликовать

1. Выберите хостинг, поддерживающий статические HTML-сайты.
2. Загрузите `index.html`, `styles.css`, `menu.js` и `favicon.svg` в корневую папку сайта, сохранив имена и регистр. `index.html` должен быть входной страницей. README публиковать необязательно.
3. Если хостинг запрашивает команду сборки, оставьте её пустой; каталог публикации — папка с этими четырьмя файлами. Не указывайте `dist`: в проекте его нет.
4. Включите HTTPS средствами хостинга. Проверьте, что главная страница и все три ресурса возвращают успешный ответ, а меню работает на опубликованном адресе.
5. Если хостинг позволяет, включите сжатие HTML/CSS/JS и проверку актуальности ресурсов через ETag или Last-Modified. Не задавайте длительный immutable-кеш для файлов без версии в имени.

Публикация в рамках аудита не выполнялась. Учётные записи, домен и конфигурация хостинга в проект не добавлены.

## Перед использованием для реального преподавателя

- Замените примеры только подтверждёнными данными и согласованными ценами.
- Добавьте действующий способ связи и проверьте его. После этого обновите предупреждения о демо и невозможности отправить заявку.
- Обновите title, description и Open Graph под реальные сведения. После выбора постоянного адреса добавьте абсолютные canonical и og:url. Сейчас они намеренно отсутствуют: адрес сайта неизвестен.
- Если появится форма, отдельно реализуйте отправку, обработку ошибок и требования к персональным данным. Сейчас форма и сбор данных отсутствуют.

## Проверка качества

Проверено по исходникам и локальными проверками PowerShell:

- Все 13 внутренних ссылок имеют существующие цели; повторяющихся ID нет.
- CSS, JS, favicon и цели aria-controls/aria-labelledby существуют.
- Есть язык страницы, viewport, один h1, последовательные заголовки, description, Open Graph и ссылка пропуска навигации.
- Меню использует обычную кнопку с aria-expanded и aria-controls, поддерживает Escape, закрытие по клику снаружи и уходу фокуса. При выборе раздела фокус переводится к нему, переход по якорю остаётся стандартным.
- При отключённом JavaScript мобильные ссылки остаются видимыми; на компьютере меню всегда доступно.
- Учтены prefers-reduced-motion, видимый фокус, области нажатия и ограничение высоты меню.
- Расчёт контраста выявил слишком светлый мелкий текст на синем фоне и подпись графика: цвета затемнены или заменены белым. Это проверка выбранных цветовых пар, а не полная сертификация доступности.
- Полезная нагрузка страницы — около 27 КБ до сжатия, четыре локальных файла включая HTML. У скрипта defer, у SVG заданы размеры. Это размер файлов, не измерение скорости загрузки.

## Что ещё проверить в браузере

Автоматизация браузера, Lighthouse и полноценный запуск JavaScript в ходе аудита не выполнялись. Node.js отсутствует в PATH. Не проверены фактическое отображение, Core Web Vitals, сетевое время загрузки, скринридеры, реальные устройства и поведение опубликованного хостинга.

Ручной чек-лист:

1. Открыть ширины 320, 360, 393, 760, 761, 1024 и 1440 px, а также альбомную ориентацию. Убедиться, что нет горизонтальной прокрутки и перекрытия текста.
2. Проверить масштаб 200% и 400%, увеличение системного шрифта и короткое окно по высоте.
3. На мобильной ширине открыть меню, выбрать каждый раздел, закрыть кликом снаружи и Escape. Проверить переключение между мобильной и десктопной шириной с открытым меню.
4. Пройти страницу клавишей Tab: Enter/Space открывают меню; Escape возвращает фокус кнопке; после выбора пункта фокус находится у раздела. Ссылка пропуска навигации ведёт к содержимому.
5. Отключить JavaScript: все ссылки навигации должны оставаться доступны. Включить уменьшение движения: плавная прокрутка и эффекты движения должны отключиться.
6. Проверить Chrome, Firefox, Safari и скринридер; запустить Lighthouse на опубликованном HTTPS-адресе в мобильном режиме.

Сохранена общая визуальная концепция. Сайт остаётся демонстрацией, а не готовым каналом приёма заявок.
